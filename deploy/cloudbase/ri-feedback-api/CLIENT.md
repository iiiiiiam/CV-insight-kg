# 云反馈手动工具

这是独立的 Windows 控制台工具，需要 Python 3.10 及以上，不需要安装依赖。支持反馈提交、手动查回复、团队处理；尚未接入主软件界面，不会修改本地公共知识或图谱。

## 启动

在仓库根目录打开 PowerShell：

```powershell
python deploy/cloudbase/ri-feedback-api/client.py --data-dir .cache/cloudbase/my-feedback
```

收到独立交付 ZIP 时，将 `ri-feedback-client.zip` 解压到自己选择的 D 盘目录，进入该目录执行：

```powershell
python client.py
```

独立包默认保存到脚本旁的 `local-data`。在两种启动方式之间切换时，指定同一个 `--data-dir` 才能看到同一份记录。启动不联网；服务地址默认指向当前试接环境，也可以通过 `--url` 指定其他已部署的 HTTPS 网关 `/feedback` 地址。

## 菜单怎么用

| 菜单 | 行为与云端请求 |
| --- | --- |
| 1 本地记录 | 展示已保存状态和回复，0 次请求 |
| 2 新建反馈 | 填说明和可选论文编号；先保存草稿，0 次请求 |
| 3 发送/重试一条 | 输入试用凭证，选择原记录发送；通常 1 次云函数调用 |
| 4 查一条回复 | 按记录保存的查询凭证查询，1 次请求 |
| 5 团队列表/处理 | 输入团队凭证；列最近 20 条用 1 次请求，确认处理再用 1 次 |
| 6 重新输入凭证 | 清除工具持有的会话凭证引用，下一次操作重新输入 |
| 0 退出 | 保留本地记录，无后台任务 |

试用凭证对应 `RI_FEEDBACK_PILOT_TOKEN`，团队凭证对应 `RI_FEEDBACK_ADMIN_TOKEN`。输入时不显示，程序不会保存这两种共享凭证，也不需要 CloudBase API Key。凭证和链接不作为命令行参数传递。

## 失败怎么办

发送前已经保存稳定的安装编号、反馈编号、内容和单条查询凭证。网络超时时，选择菜单 3 的**同一条原记录**手动重试，服务端用原编号去重。不要新建一条相同反馈重试。程序不会自动重试，不轮询，也不会一次查询全部历史记录。

团队更新带版本号；冲突时重新进入团队列表查看最新记录，再决定如何处理。确认处理后，如果网络超时，结果可能已经保存，先刷新列表再判断，避免盲目重复更新。

本地记录使用 Windows DPAPI 加密保存，绑定当前 Windows 账户。不要删除或丢失该目录；仅备份文件不保证能在另一账户/另一电脑解密。当前没有跨设备迁移或查询凭证找回功能。共享凭证未持久化，重启需重新输入。

同一目录只允许一个工具窗口；异常退出可能留下 `session.lock`，确认工具已关闭后才手动删除该锁文件，不要删除 `feedback.dpapi`。读取失败不会清空原存档。

## 交付范围

适用于封闭小范围试接：少量文字反馈和手动回复。团队列表目前只取最近 20 条，无分页；没有云端撤回、删除、完整处理历史、自动知识同步或正式用户身份体系。不要公开分发团队凭证或服务端 API Key。正式软件接入和完整同步另行实现。

## 复用验证

在仓库根目录执行离线功能检查：

```powershell
python deploy/cloudbase/ri-feedback-api/test_client.py
node --test deploy/cloudbase/ri-feedback-api/index.test.js
```

两条命令都不调用云端。客户端检查覆盖持久化重开、超时后重试同一请求、回复缓存、处理版本及凭证保护；云端已有测试可在后续规范测试中直接复用。本阶段不作为第二轮独立测试验收。

其中 4 项为模拟保护层的离线功能检查。真实 Windows DPAPI 加解密需在正常用户终端单独确认（受限执行账户无法完成）：

```powershell
python deploy/cloudbase/ri-feedback-api/test_client.py --windows-protection
```

该命令仍不联网、不用真实凭证，只在项目 `.cache/cloudbase/offline-checks` 创建临时文件。
