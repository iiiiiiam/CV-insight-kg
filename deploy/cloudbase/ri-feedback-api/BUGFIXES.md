# 云反馈接入与兼容问题修复记录

日期：2026-11-27。供交接、文档及展示复用。以下区分真实反馈、代码分析和离线验证，不将简单功能验证表述为完整验收。

| 编号 | 现象与原因 | 修复 | 验证与结论 |
| --- | --- | --- | --- |
| CF-01 | Windows 登录页白屏；系统 `.js` MIME 关联可能为 text/plain，浏览器在 nosniff 下拒绝模块 | 后台进程显式注册正确 JS/MJS MIME，不修改注册表 | `test_static_assets.py` 模拟错误关联通过；用户重启后可进入并登录 |
| CF-02 | 用户主状态仍“待处理”，团队回执却“已处理”；本机审核状态和云回复状态是两套记录 | 已送达反馈主状态优先显示云状态，说明和回复同卡展示 | 真实回传可见 resolved / dismissed 与正确中文回复；前端回执回归通过 |
| CF-03 | 云端旧反馈已处理、本机仍 open，再提同条目被当作重复，列表条数和旧内容不变 | 提交使用当前所有者的缓存终态回执，将这些记录排除出本次去重候选；真正待处理的重复仍去重，不增加云查询 | 回归模拟“云 resolved、本机 open → 新编号送达 → 再点去重”；用户确认新增第 4 条并跑通闭环 |
| CF-04 | 任一旧回执查询失败，Promise.all 使整批状态更新失败；笼统报错掩盖成功记录 | 逐条刷新、保留已有回复、每条显示错误；已撤回且 404 的旧记录保留为历史存档 | 前端测试覆盖单条失败不影响其他记录、已撤回 404 不报当前提交错误 |
| CF-05 | 公共修正与团队回复分别在两个入口，用户难以判断同一反馈是否处理 | 一个列表合并本机/云副本，同面板核对、修正、回复；重复点击收起；移除旧分离面板 | 用户已在新版统一流程保存“保留原结果”及回复，提交端查询成功 |
| CF-06 | 本机知识处理成功而网络失败时，重做保存可能重复修改知识 | 同一知识事务持久化回复意图；失败保留待发送，仅重试发送；回复版本冲突不自动覆盖 | 离线模拟网络失败后重试，处理记录保持不变；撤回恢复待处理也有定向断言 |
| CF-07 | LVIS 详情固定高度加原文内部滚动，反馈入口和提示被长文本遮住 | 详情取消固定高度，反馈入口放在原文前并常显，上下文按需展开；我的反馈移出详情框；错误靠近提交按钮 | 类型检查和构建通过；用户后续截图显示新反馈及回复。非完整屏幕尺寸视觉验收 |
| CF-08 | 管理员账号和改密放在知识管理中，功能归属不清；页面出现验收步骤及接口细节 | 复用原账号页集中账号/密码管理，知识管理保留反馈与批次；清除会话页验收清单和技术展示 | 构建通过；账号页位置用户暂接受，后续与组长沟通；无新增主路由 |
| CF-09 | “刷新反馈”和“获取团队新反馈”并存，名称无法准确表达作用 | 合为“刷新反馈列表”；团队权限有效时云刷新，否则本机刷新，打开页面不自动访问云 | 构建通过；不为文案调整重复真实请求 |
