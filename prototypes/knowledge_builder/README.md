# 知识构建工作台原型

本地 Streamlit 页面，重点试用论文、候选、证据、核对、保存恢复、导出和质量检查。
不代替团队正式主前端；Neo4j、登录与正式接口明确保留为未接入。

## 启动

从仓库根目录，复用 insight 环境：

```powershell
conda activate insight
python -m scripts.knowledge_builder.workbench
```

浏览器打开 http://127.0.0.1:8501 。不会自动弹浏览器。
端口被占用时用 `--port 8502`，再打开相应地址。自己启动的终端可按 Ctrl+C 停止。
原 A 入口 `python run.py` 和端口 8000 不变，不需要为本原型启动它。

本轮已确认现有环境安装 Streamlit 1.66.1，无需重建环境。
其他机器仅在需要此原型时安装可选 `requirements-prototype.txt`；核心命令不依赖 Streamlit，团队基础依赖文件未改。

## 建议试用顺序

1. 概览：看 20 篇论文、候选数量及哪些工作仍待真实验证。
2. 论文与候选：按关键词、年份、方法、主题组合筛选，选择论文查看原文、表格和本地关系图。
3. 候选核对：先看证据，确实认可后再填写姓名、理由并确认；可驳回、改名或重新检查。
4. 导出与质量：下载三种状态 JSON 或完整 ZIP，也可保存文件包、生成五篇验证材料。

关系需要先确认两个端点，页面会给出跳转按钮；改名不改变来源原文；撤回实体会让相关确认关系退回待审。
每次操作先校验并保存，成功后更新页面。其他窗口已经修改存档时会拒绝覆盖，可用左侧“重新载入本地进度”。
这里只是开发核对工具，不要求普通查看者逐条审核，姓名记录也不是登录认证。

## 代码边界

| 文件 | 职责 |
| --- | --- |
| app.py | Streamlit 页面与表单 |
| presentation.py | 中文标签、证据高亮和安全转义的 SVG 关系示意 |
| ../../src/knowledge_builder/workbench.py | 不依赖 Streamlit 的应用协调层 |
| ../../scripts/knowledge_builder/workbench.py | 可选原型启动入口 |

核心仍处理普通 Python 数据，不接收 Streamlit 会话对象。页面状态只是持有一个 Workbench 实例，审核规则不在页面重复实现。
默认数据在 `data/knowledge_builder/`。测试或隔离试用可通过 `KNOWLEDGE_WORKBENCH_DATA` 指定单独目录，页面和 CLI 可复用同一存档格式。
左侧可以选择原始 8 词条版本以兼容旧存档，不会自动迁移旧决定到新词表。

图是本地候选预览，最多展示 13 个对象并提示实际数量，不是 Neo4j 查询，也没有伪造节点点击联动。
原型只监听本机回环地址，没有实现正式用户系统、权限控制和团队部署。

## 验证

已用 Streamlit AppTest 检查四个页面、空筛选、真实保存恢复、端点约束跳转、导出与验证材料按钮。
测试存档只在临时目录，所有自动确认都标记为程序测试，不计作真人确认。
本机启动与 HTTP 健康检查另行执行；没有把 AppTest 当成真实浏览器截图验收。
