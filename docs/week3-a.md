## 本分支的数据与启动

在仓库根目录安装依赖后执行：

```bash
python -m pip install -r requirements-dev.txt
python -m server.run_local --demo
```

打开终端显示的 `/preview` 地址。首次启动从现有文件自动初始化：

| 用途 | 数量 | 范围 |
| --- | ---: | --- |
| 已入库论文 | 420 | CVPR 380、ICCV 20、ECCV 20 |
| 可手动导入论文 | 2,534 | CVPR 2,334、ICCV 200 |

选择会议和数量后点击“导入下一批”，论文真实入库并生成批次。已有库继续保留导入和撤回结果。

## 页面展示与操作

- 每日图表上方：蓝色实心为手动新增、绿色斜纹为自动新增；下方橙色斜纹为撤回。点击日期可查看新增和撤回明细。
- 今日指标分别展示新增、撤回与净增，首页有效论文总数按当前状态计算。
- 在论文导入或导入记录页选择撤回批次，核对编号、时间和论文数，再填写原因确认。
- 撤回后独有论文退出当前库并回到补充库，共有论文继续有效；历史论文和导出保留。
- 页面编号使用 M/A 前缀；交接文件的原 `batch_id`、`batch_code` 和修订号保持稳定。

演示中的初始日期及自动采集方式为模拟展示，新导入和撤回记录实际执行时间。

## A/B 文件交接

现有交接文件放在 `examples/week3_handoff/`：

1. B 在“用户反馈处理 → 论文批次”导入 `01-first-batch.json`，应为 20 篇；重发原文件保持 20 篇。
2. 导入 `02-second-batch.json`，应为 30 篇；共有论文只保留一份。
3. 在 B 的批次列表撤回 `BATCH-000002`，应恢复为 20 篇；第二批独有 10 篇移除，共有 10 篇保留。
4. 导出当前有效知识，核对撤回前 30、撤回后 20；重复撤回保持结果稳定。

本次已用这两份原文件对 B 的 `knowledge-topics`（`c7f8989`）接收服务完成隔离 HTTP 及完整有效知识导出验证。`07-b-receiver-results.json` 保存实际回执和文件校验值，`04-second-batch-withdrawal.json` 用于核对 A 撤回记录。

第二批 A 的统计为新增 10、重复 5、更新 5；B 的回执为新增 10、重复 7、更新 3。A 包含来源元数据变化，B 比较实际论文输入，其中 2 篇变化没有改变 B 输入。

B 首次成功导入会切换到批次管理输入集合。本轮数量以独立空验收账本为起点；B 本人环境的确认由实际操作后记录。
