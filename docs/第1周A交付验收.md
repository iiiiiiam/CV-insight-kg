# 第 1 周 A 交付验收

本次对应 `week1_原型计划.md` 中 A 的成员交付标准：明确样本范围与基准、搭建采集任务及 MySQL 表、完成去重导入接口、管理页与重复导入验证。

## 固定数据范围

- 基准编号：`week1-cvpr2024-detection-v1`，版本 1。
- 来源：OpenAlex；会议年度：CVPR 2024；方向：标题含 object detection、DETR 或 YOLO，且有摘要。
- 范围：固定 20 篇真实论文，作为本周原型样本，不代表完整会议或正式评估集。
- 基准清单：[JSON](../examples/week1_baseline.json)、[CSV](../examples/week1_baseline.csv)。JSON 同时保存样本文件 SHA256，导入前核对完整性与逐篇标识。
- B/C/D 跨机器对齐使用 `openalex_id`；内部 `papers.id` 在重复导入时保持稳定。

## A 标准与对应实现

| 要求 | 实现与验证 |
| --- | --- |
| 20—30 篇真实论文、清洗、去重、重复导入 | 固定 20 篇；空库两次 HTTP 导入后仍是 20 篇，论文 ID 保持不变 |
| 标题、年份、来源、稳定 ID 和批次号 | `papers`、`paper_sources` 保存论文和原始来源；`paper_batches(job_id, paper_id)` 为每次导入建立关联；每个批次形如 `BATCH-000001` |
| MySQL 原始记录与任务表可创建并读写 | 在独立空 MySQL 库用 `app.verify_mysql` 验证建表、20 条原始记录、2 个任务/批次、40 条论文批次关联及重复导入 |
| 受保护的去重导入接口 | `POST /api/admin/imports` 导入固定样本；无令牌 401、错误令牌 403；校验失败 422；同范围任务冲突 409 |
| 简化管理页显示真实结果 | `/admin` 可导入、重复导入、查看任务计数、基准编号、真实论文列表与日志，按批次导出 CSV |
| 采集与任务骨架 | `Source`、`Job`、`JobEvent`；DBLP/OpenAlex 在线任务、重试和中断重跑；固定样本无需 worker 或外网 |
| 可交接的运行环境 | README 包含本地 SQLite 与 Docker 方式；交接包包含依赖、真实样本、初始化脚本与自动验收脚本 |

## A 的接口与模块约定

- `app.datasets.load_sample`：只接收已知基准编号，验证文件校验值、20 篇清单、来源与年度。
- `app.datasets.import_sample`：固定样本去重导入；每次新导入创建新 Job 作为批次；失败重试复用原批次。
- `app.ingest.upsert_paper`：清洗后论文与来源的稳定写入；通过 `job` 参数记录批次关联。CLI 文件导入和在线采集也记录关联。
- `GET /api/admin/datasets`：基准清单；`POST /api/admin/imports`：受保护导入。
- `GET /api/admin/jobs/{id}`：计数与日志；`GET /api/admin/jobs/{id}/papers`：批次论文。
- `GET /api/papers?batch_id={id}`、论文详情的 `batch_ids`/`batches`、CSV 的 `batch_ids_json`：供 B/C/D 关联批次与证据。
- API 实现版本 0.3.0；请求与返回结构见运行中的 `/docs` 和 [接口快照](week1_api.openapi.json)。管理员登录会话与退出撤销仍由 D 的功能接入，本次 A 接口沿用管理员令牌。

## 复现步骤

1. 按 README 创建虚拟环境、安装依赖，运行 `python scripts/init_project.py`。
2. 为演示空库导入，可以先不执行 `app.seed`，直接运行 `python -m app.dev`。
3. 打开 `/admin`，页面会自动显示本机演示数据。
4. 点击“导入固定 20 篇样本”，核对成功 20、失败 0、批次论文 20。
5. 再次点击相同按钮，核对数据库总数仍为 20，批次号新增，每篇论文的 ID 保持不变。
6. 打开批次详情并导出 CSV；运行 `python scripts/verify_week1.py --output data/verification/week1.json` 保存自动记录。



演示入口 `python run.py` 现使用本机免手填凭据模式，监听回环地址。 上文中的 401/403 验证对应受保护运行模式，正式登录、退出和导入鉴权仍需与 D 的会话机制接入。
