## B：已实现的行为

- 子方向：17 个一级标签和“其他”，通常 1 个，少数 2～3 个。原 topic、task 不改名、不删除。
- 单篇关联图：新增子方向的只读展示节点及“属于研究方向”连线；稳定布局、较大文字，关系文字按需显示，重新布局按钮可显式改变排列。不使用 Neo4j。
- 批次：重复去重、后接收的有效内容优先、撤回时保留其他批次来源并恢复旧内容，失败整批不生效且可重试。
- 首次成功导入会切换到批次论文范围，原 150 篇不会自动合并；全部撤回后为空，不恢复旧样本。批次反馈使用独立存档。
- 来源增强：导入后后台复用旧语料/请求缓存并获取缺失来源。读取和导出不联网；失败仍保留规则结果，可重试。按论文内容保存，更新不误用旧记录，撤回可恢复旧版本记录。
- 有效导出：沿用 effective 格式和既有读取接口，反映当前结果和公共修正，浏览器个人修改不进入公共数据。
- 管理员页：沿用 `/admin/knowledge-feedback`，页内切换用户反馈/论文批次，公用导出入口；不新增导航层级。

## C：正式图谱模块需要知道

请按完整快照接收，撤回后缺失的论文/关联应退出当前展示，不能只追加。空快照发布是否支持仍需确认；新批次来源补充途中和完成后可能有不同版本。自动结果可展示但不能标成人工确认。

已从源码确认：C 论文详情抽屉复用 B 的 KnowledgeEvidence，因此合并后可展示更新的单篇图。但它读取的是 B 当前输入，并未固定到 C 的历史发布批次；旧 C 批次与 B 当前内容不保证一致，且论文必须在 B 当前范围内。

## 本轮 B 子方向搜索接口

`GET /api/knowledge/research-directions`：公开读取，不需管理员会话，不联网补充。

响应：`directions: [{id, name, count}]` 和 `papers: [{paper_id, title, year, venue, research_directions: [{id, name}]}]`。包含 17 个方向和“其他”，零篇标签也返回。数量按该方向涉及的论文计数；少数论文多方向，因此标签计数相加可能大于总论文数。

B 页面将标题关键词与单个方向取交集，筛当前全部输入；筛选不擅自切换正在阅读的论文，无匹配结果会提示。方向写入 URL，刷新可保留；标题关键词仍沿用原来的页面内输入行为。旧 `/api/knowledge/papers` 响应不变。

查看新功能：重启 `python -m server.run` 加载新增接口，再打开 `/research/knowledge`。点击子方向标签可筛选，点击“全部”清除方向筛选；标题框可继续缩小范围。标签显示 0 时仍可选，页面会明确显示无匹配论文。此处不改变分类规则，只提供读取和筛选。
