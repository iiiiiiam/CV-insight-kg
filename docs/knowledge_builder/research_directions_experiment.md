# 一级研究子方向：抽样实验与推荐方案

实施进展：本文记录的是前置调查，后续已在 `knowledge-topics` 采用组合线索并增加“默认一个、最多三个、无法分类为其他”的选择规则。当前运行规则、结果分布及接口字段以 [有效结果交接说明](effective_export.md) 最前面的“当前子方向规则”为准。本文 26/33/32 的对比数据保留，不替换成开发调整后的结果，也不把本次样本当独立测试集。

日期：2026-11-13。本轮仅调查和编写方案，**未修改业务代码、分类规则、前端或 C 模块，没有把实验论文加入正式输入**。当前分支 `knowledge-topics` 上已有的 tasks 分类代码来自前一轮，仍是试验实现，不表示本方案已经接入。

## 1. 先确定我们要解决什么

产品中的主方向先统一为“计算机视觉”，下面只整理一层常用子方向，如目标检测、图像分割、三维视觉。不搭多级分类树，不新增必须人工审核的流程，也不要求每篇强行分到某个方向。

现有 `topic` 和 `task` 的含义暂时保留。产品子方向是由来源线索经归类规则整理出的补充信息；既不直接等于任务标签，也不直接等于 OpenAlex 学科层级。前端最终叫“研究子方向”还是别的名称，后续与组员确认。

## 2. 论文从哪里来，怎么抽的

使用 A 已有的两份原始论文文件：

- `examples/cvpr_2024_full/cvpr_2024.jsonl`：CVPR 2024。
- `examples/supplementary_pool/iccv_2023.jsonl`：ICCV 2023。

排除之前正式使用的 150 篇和上一轮调查的 60 篇；仅保留有作者、摘要的记录。按稳定论文 ID 排序后，使用固定随机种子 `20261113`，依次从 CVPR、ICCV 各随机抽取 20 篇，共 40 篇。固定种子用于重现名单，不按识别效果挑论文。本轮未 fetch 远程分支，代表当前本地 A 文件，不代表 A 所有最新远程数据。

这不是对所有会议论文的统计抽样：会议池本身有选择偏差，两个会议采用相同样本数也不代表其真实论文占比；ECCV 等本轮没有覆盖。

随后只读查询外部来源：

| 可获得的信息 | 实际情况 |
| --- | --- |
| OpenAlex 论文记录 | 40/40 |
| OpenAlex 主题、关键词 | 40/40 均有 |
| 目录匹配到同一篇记录 | 39/40 |
| 目录 tasks 非空 | 29/40 |

目录沿用现有标题、作者、年份匹配逻辑，请求的是 `paperswithcode.co`，作为辅助来源，不称为原作者的官方标注。OpenAlex 的主题和关键词也是来源自动分类，不能直接当作人工标准答案。

## 3. 比较的三种方式

为方便横向比较，三组统一使用同一范围的 12 类方向：图像分类与识别、目标检测、图像分割、目标跟踪、姿态与动作理解、三维视觉、深度与几何估计、图像与视频生成、图像与视频编辑、图像恢复与增强、视觉检索、视觉语言理解。名称可调整，本次不冻结为最终产品清单。

### A：只看 tasks

沿用前一轮任务归类表，并投影到上述共同方向范围。目录有明确受支持的任务就归类；没有任务或规则不认识时留空。

优点是简单；问题是有些论文的 tasks 为空，有些 tasks 又把次要任务一起列出。不是目录匹配到论文就一定有任务字段。

### B：直接合并 OpenAlex 线索

对论文标题、OpenAlex 关键词、首选主题分别进行明确短语匹配，然后直接合并方向。不是看到 Transformer、Diffusion 就强行判断方向；依然需要任务或方向短语。

覆盖较高，但容易把方法背景、应用场景和次要任务也混入方向列表。

### C：明确标题优先，关键词需要补充印证

本轮实验采用的明确规则是：

1. 标题直接命中一个明确的方向短语，可以给出相应方向。
2. 关键词命中的方向，同时得到目录 tasks 或 OpenAlex 首选主题支持，才进入本轮主要归类结果。
3. 其他单一来源的线索只保留为补充候选，不自动加入主要归类。

等价表达：`标题命中 OR（关键词命中 AND（tasks 命中 OR 首选主题命中））`。

这里只是来源一致性规则，不是概率模型，也不意味着两条来源就是独立证据或一定正确。本次没有利用摘要判断否定、对比和主次；标题本身也可能描述对比对象，后续仍需注意。

## 4. 实际结果

| 方式 | 至少得到一个方向的论文 | 方向归属总条数 |
| --- | --- | --- |
| A：tasks 单独归类 | 26/40（65%） | 35 |
| B：OpenAlex 标题、关键词、首选主题直接合并 | 33/40（82.5%） | 43 |
| C：明确标题或有补充印证的关键词 | 32/40（80%） | 37 |

同一篇可以属于多个方向，所以归属条数可以大于论文数。这里都是**规则覆盖率，不是准确率**；不能因为 C 少给了几条标签就声称更准确。

C 相对 A：补回了 7 篇 A 无法归类的论文，同时让 1 篇仅有目录任务支持的论文暂时不归类，净增加 6 篇。CVPR 20 篇中 A/B/C 覆盖为 15/17/17；ICCV 20 篇中为 11/16/15。

此次在查看元数据后编写实验短语规则，因此属于探索性试验，不是独立封存评估集。没有完整人工标准答案，不提供精确率、召回率或“已经达到多少正确率”的结论。

## 5. 哪些真实例子说明了问题

### 补回来源遗漏：NeuS2

论文：`NeuS2: Fast Learning of Neural Implicit Surfaces for Multi-view Reconstruction`，可理解为“用于多视角重建的快速神经隐式表面学习”。目录没有可用 tasks。标题明确说多视角重建，OpenAlex 关键词也提供相应信息，因此 C 可以归到“三维视觉”。不需要人为给这篇添加答案。

### 补回任务字段缺失：视觉跟踪论文

`Exploring Lightweight Hierarchical Vision Transformers for Efficient Visual Tracking`：标题明确“视觉跟踪”，OpenAlex 关键词也包含“视觉目标跟踪”，但目录没有可用 tasks。C 可以归到“目标跟踪”。说明任务字段缺失不应成为唯一阻断条件。

### 减少泛泛的三维标签：SparseBEV

`SparseBEV: High-Performance Sparse 3D Object Detection from Multi-Camera Videos`：tasks 提供“三维目标检测”和“三维理解”。A 会给“目标检测、三维视觉”，C 本轮主要保留标题明确的“目标检测”。这不是说三维视觉一定错误，而是不用因为出现 3D 就把每篇都附加一个大类；是否需要这种重叠，应在产品分类定义中统一。

### 避免所有任务照单全收：CDS 图像编辑论文

`Contrastive Denoising Score for Text-Guided Latent Diffusion Image Editing`：目录任务映射后涉及编辑、生成、三维视觉，C 主要保留“图像与视频编辑”。摘要确实还讨论生成模型和 NeRF 编辑，所以不能说其他标签完全错误；但主列表只放更明确的方向，更适合用户快速筛选。

### 真正跨方向：Residual Denoising Diffusion Models

这篇摘要明确介绍统一图像生成和恢复的模型，关键词与 tasks 也包含二者。C 保留“图像与视频生成、图像恢复与增强”。不应强行要求每篇只能有一个方向。

### 条件过严也会漏分：ViperGPT

`ViperGPT: Visual Inference via Python Execution for Reasoning`：关键词含视觉问答和视觉语言模型，但目录 tasks 为空，首选主题“多模态机器学习应用”又比较宽。本轮 C 暂未归类。阅读摘要可看出视觉语言理解很有理由，但不能把这次人的判断直接写成该论文的专属规则。

它说明后续可研究用摘要中的明确任务表达辅助，而不是立刻放宽所有关键词。当前 C 不是“完美方案”。

### 不在现有清单里：异常检测、水印和轻量化

FastRecon 的工业异常检测、Stable Signature 的水印、MobileNet/ViT 的效率优化，在这套 12 类里不易安排。暂未归类优于硬塞进目标检测、生成或分类。是否增加“视觉异常检测”“视觉安全”“视觉模型效率”等方向，后续按实际论文规模和组内需求决定，本轮不扩张。

## 6. 推荐先定的方案

**推荐采用 C 的证据优先思路作为下一步实现基线，不采用单一 subfield，也不把所有来源标签直接取并集。**

- 主方向统一“计算机视觉”，子方向只一层。现有 topic/task 功能保留。
- 明确标题是优先线索；关键词经目录任务或足够具体的主题印证后归类。
- OpenAlex subfield 仅保留所属学科背景，不当成产品子方向，不因 subfield 不是 CV 就删除论文。
- 泛主题如“高级神经网络应用”“多模态机器学习应用”不自动对应某个具体任务方向。
- 单来源线索保留但不默认全部展示；后续可用通用的摘要任务表达补漏，先不承诺完整语义分析。
- 分类规则对所有论文统一应用，不写逐篇答案，不引入逐条人工审核。用户反馈仍是可选渠道，不作为分类能否完成的前提。
- 不强求覆盖每篇，也不写死“准确率80%”；本轮 80% 只指样本覆盖。

这里的“主要结果”表示按当前规则选择展示的方向，**不是已经精确判断了论文主贡献**。如果产品想要严格的“主要研究方向”，还需进一步定义主次判断规则；本阶段使用“研究子方向”更合适。

## 7. 将来如何限制在 B 内落地

本轮不实施，以下只规定推荐边界：

1. 仍沿用 `source_classifications` 的补充分类记录，与原 topic 区分；不新增实体类别或关系。已有 tasks-only 试验需调整后才算采用本方案。
2. 每条保留稳定方向键、显示名称、规则版本，以及具体命中的标题文字、关键词、主题/任务名称、来源地址和字段位置。来源分类不冒充原文摘要证据。
3. 区分可展示结果和补充候选。不能把未选中的候选塞进现有数组让网页自动全部显示；具体怎样编码候选，需要先与读取接口对齐。
4. 分类变化纳入有效结果版本。C 接收的是 B 已选择的结果，不要求 C 重做分类；但增加筛选、方向节点或统计仍需相应模块接入。
5. 暂不改 C、A 或正式图谱，也不在用户打开页面时联网。来源查询在离线准备阶段完成，运行时读取冻结记录。
6. 先用小批论文验证阅读与导出一致、分类版本稳定及旧读取器兼容，再讨论扩展到全部论文。Neo4j 写入和页面完整联动留给相应成员联调。
